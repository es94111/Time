# Feature Specification: 電腦資訊監控紀錄

**Feature Branch**: `002-system-metrics`  
**Created**: 2026-07-01  
**Status**: Draft  
**Input**: User description: "新增 紀錄電腦資訊，我要紀錄 CUP 使用率﹑記憶體 使用率﹑所有硬碟的寫入與讀取速度﹑網路 傳輸與接收速度﹑GPU 使用率與GPU記憶體使用率"

## Clarifications

### Session 2026-07-01

- Q: 取樣週期的預設值為何？ → A: 預設每 1 秒取樣，並提供使用者自訂輸入其他取樣秒數。
- Q: 歷史紀錄的保留策略預設為何？ → A: 預設保留 30 天，並提供使用者自訂保留天數。
- Q: 背景紀錄的資源負擔上限（量化 SC-006）為何？ → A: 閒置時本工具平均 CPU < 2%、記憶體使用 < 150 MB。
- Q: GPU 記憶體使用率的紀錄方式為何？ → A: 同時保存已用量與總量（位元組），百分比由兩者推算。
- Q: 網路速度以整機合計或逐一網卡紀錄？ → A: 逐一網路介面分別紀錄（與硬碟／GPU 一致），可另計合計。
- Q: 自訂取樣週期的允許範圍為何？ → A: 允許 1～3600 秒（最快每 1 秒、最慢每 1 小時）。
- Q: 自訂保留天數的允許範圍為何？ → A: 允許 1～3650 天（最短 1 天、最長約 10 年）。
- Q: 長區間歷史趨勢如何避免逐筆回傳造成過重查詢？ → A: 查詢時依區間長度自動降取樣（分鐘／小時彙總）呈現，原始逐筆樣本仍完整保留。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 持續紀錄整機資源使用狀況 (Priority: P1)

使用者希望本工具在背景持續量測並紀錄整台電腦的核心資源指標——CPU 使用率、記憶體使用率、各硬碟讀寫速度、網路上傳與下載速度、以及每張 GPU 的使用率與 GPU 記憶體使用率——好讓自己日後能回顧「這台電腦在某段時間到底忙不忙、是什麼資源被吃滿」。

**Why this priority**: 這是本功能的核心價值。沒有可靠、持續的量測與紀錄，其他一切（檢視、分析）都無從談起。單獨交付這一項，使用者就已能累積可回顧的效能歷史資料。

**Independent Test**: 讓工具執行一段時間（例如 10 分鐘），期間刻意進行高負載操作（複製大檔、下載檔案、跑 GPU 運算），事後確認資料庫中存在對應時間區間、且數值隨負載明顯變化的紀錄。

**Acceptance Scenarios**:

1. **Given** 工具正在使用者工作階段中執行，**When** 經過一個取樣週期，**Then** 系統寫入一筆含時間戳記與當下所有指標（CPU、記憶體、各硬碟讀寫、各網路介面收發、各 GPU 使用率與 GPU 記憶體）的紀錄。
2. **Given** 電腦裝有多顆硬碟，**When** 系統取樣硬碟指標，**Then** 每一顆硬碟的讀取與寫入速度分別被個別紀錄，可辨識是哪一顆硬碟。
3. **Given** 電腦裝有多張 GPU，**When** 系統取樣 GPU 指標，**Then** 每張 GPU 的使用率與 GPU 記憶體使用率分別被個別紀錄，可辨識是哪一張 GPU。
4. **Given** 高負載持續進行，**When** 使用者事後查閱該時段紀錄，**Then** 各指標數值反映當時的實際負載（例如下載時網路接收速度明顯上升）。

---

### User Story 2 - 即時檢視目前資源狀態 (Priority: P2)

使用者希望能在介面上看到「現在這一刻」各項指標的即時數值，作為快速健檢，不必翻歷史資料就能知道當下哪個資源吃緊。

**Why this priority**: 提升日常實用性，但仰賴 P1 的量測能力。即使沒有即時畫面，只要 P1 的紀錄存在，價值仍成立，故列為 P2。

**Independent Test**: 開啟即時檢視畫面，於另一程式製造某類負載（如大量寫入硬碟），確認畫面上對應指標於數秒內反映變化。

**Acceptance Scenarios**:

1. **Given** 即時檢視畫面開啟，**When** 各指標更新，**Then** 畫面於數秒內顯示最新的 CPU、記憶體、各硬碟讀寫、網路收發、各 GPU 使用率與 GPU 記憶體數值。
2. **Given** 某項指標暫時無法取得（如系統未安裝獨立 GPU），**When** 畫面渲染，**Then** 該項以明確狀態（例如「不適用」或「無資料」）呈現，而非顯示錯誤或誤導性的 0。

---

### User Story 3 - 回顧歷史趨勢 (Priority: P3)

使用者希望以時間為軸回顧一段區間內各指標的變化趨勢，找出資源尖峰發生的時間點。

**Why this priority**: 提供分析深度，屬加值功能；仰賴 P1 已累積的歷史資料，故優先度最低。

**Independent Test**: 選定一段已有紀錄的時間區間，檢視趨勢呈現，確認尖峰時間點與實際發生的高負載事件吻合。

**Acceptance Scenarios**:

1. **Given** 已累積一段歷史紀錄，**When** 使用者選定時間區間檢視，**Then** 系統呈現該區間內各指標隨時間的變化。
2. **Given** 選定區間內無任何紀錄（工具當時未執行），**When** 使用者檢視，**Then** 系統明確標示該區間無資料。
3. **Given** 使用者選取跨越很長時間（如整年）的區間，**When** 系統呈現趨勢，**Then** 系統以自動降取樣後的彙總資料點呈現（而非逐筆原始樣本），趨勢仍能反映實際尖峰時段，且回應維持流暢。

---

### Edge Cases

- 取樣當下某項指標暫時讀取失敗（如驅動忙碌、感測器逾時）時，系統應如何處理？（預期：紀錄該筆缺值而非中斷整體取樣，其餘指標照常寫入。）
- 執行期間有硬碟、GPU、或網路介面被插入或移除時，如何處理裝置清單變動？（預期：後續取樣反映新的裝置組合，歷史紀錄仍保留已移除裝置的資料。）
- 電腦進入睡眠 / 休眠再喚醒後，紀錄時間軸出現空缺時如何呈現？（預期：以「無資料」表示空缺，不以內插假造數值。）
- 系統完全閒置（各指標接近 0）時仍應照常紀錄，以證明「當時電腦是閒置的」。
- 長時間執行導致紀錄量龐大時，需依保留策略自動清理過期資料，避免無限成長。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 依設定的取樣週期（預設每 1 秒，見 FR-012），持續量測並紀錄 CPU 整體使用率（百分比）。
- **FR-002**: 系統 MUST 量測並紀錄實體記憶體使用率（百分比）。
- **FR-003**: 系統 MUST 為電腦上每一顆硬碟分別量測並紀錄其寫入速度與讀取速度（資料量／每秒），且每筆紀錄可辨識所屬硬碟。
- **FR-004**: 系統 MUST 為電腦上每一個網路介面分別量測並紀錄其傳輸（上傳）速度與接收（下載）速度（資料量／每秒），且每筆紀錄可辨識所屬網路介面；整機合計流量 MUST 可由各介面加總得出。
- **FR-005**: 系統 MUST 為電腦上每一張 GPU 分別量測並紀錄其使用率（百分比）與 GPU 記憶體使用狀況；GPU 記憶體 MUST 同時保存已用量與總量（位元組），使用率百分比由兩者推算，且每筆紀錄可辨識所屬 GPU。
- **FR-006**: 系統 MUST 為每一筆量測附上時間戳記，並將紀錄持久化保存，供事後回顧。
- **FR-007**: 當某項指標於取樣當下無法取得時，系統 MUST 將該項標記為缺值，並持續紀錄其餘可取得的指標，不得因此中斷整體紀錄流程。
- **FR-008**: 系統 MUST 能在偵測到裝置（硬碟、GPU、網路介面）新增或移除後，於後續取樣中反映最新的裝置組合。
- **FR-009**: 系統 MUST 提供即時檢視，顯示各項指標的最新數值。
- **FR-010**: 系統 MUST 提供依時間區間回顧歷史紀錄的能力。
- **FR-011**: 系統 MUST 以保留 30 天為預設，並允許使用者自訂保留天數，允許範圍為 1～3650 天（最短 1 天、最長約 10 年）；超出範圍的輸入 MUST 被拒絕並提示使用者。超過保留期限的舊紀錄 MUST 自動清除，避免儲存空間無限成長。
- **FR-012**: 系統 MUST 以每 1 秒為預設取樣週期，並允許使用者自訂輸入其他取樣秒數，允許範圍為 1～3600 秒（最快每 1 秒、最慢每 1 小時）；超出範圍的輸入 MUST 被拒絕並提示使用者。此設計用以在資料精細度與儲存量之間取捨。
- **FR-013**: 所有紀錄 MUST 沿用本專案既有的本機加密儲存機制，與現有活動追蹤資料一致地受保護。
- **FR-014**: 回顧歷史趨勢時，系統 MUST 依所選時間區間長度自動降取樣呈現（例如較長區間改以分鐘或小時級距彙總資料點），以維持查詢與繪圖效能；原始逐筆樣本 MUST 仍完整保留，供需要精細解析度時查詢，降取樣不得竄改或內插假造原始資料。
- **FR-015**: 系統 MUST 提供啟用／停用背景指標紀錄的設定（預設啟用）；停用時 MUST 停止取樣與寫入、不再產生新紀錄，既有歷史紀錄不受影響；重新啟用後於下一取樣週期恢復紀錄。

### Key Entities *(include if feature involves data)*

- **指標樣本 (Metric Sample)**：某一時間點對整機的一次量測快照，含時間戳記，並關聯該時刻的 CPU 使用率、記憶體使用率、各硬碟讀寫速度、各網路介面收發速度、各 GPU 使用率與 GPU 記憶體使用狀況。
- **硬碟裝置 (Disk Device)**：一顆可被辨識的實體或邏輯硬碟，供讀寫速度紀錄歸屬。
- **GPU 裝置 (GPU Device)**：一張可被辨識的顯示卡，供使用率與 GPU 記憶體（已用量與總量位元組）紀錄歸屬。
- **網路介面 (Network Interface)**：一個可被辨識的網路連線來源，供傳輸／接收速度紀錄歸屬；整機合計流量為各介面之加總。
- **保留策略 (Retention Policy)**：決定歷史紀錄保存多久、逾期後如何清除的設定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 工具持續執行時，每個取樣週期都產生一筆含全部指標的紀錄，一小時內的紀錄筆數與預期取樣頻率相符（缺漏率低於 1%，睡眠／休眠造成的空缺除外）。
- **SC-002**: 使用者在製造已知負載（如下載大檔）後查閱對應時段紀錄，能明確看出該指標的上升，數值方向與實際負載一致。
- **SC-003**: 即時檢視畫面在指標變化後 3 秒內反映最新數值。
- **SC-004**: 多硬碟與多 GPU 環境下，每一顆硬碟、每一張 GPU 的數值皆能被個別區分與辨識，無混淆或遺漏。
- **SC-005**: 連續執行超過保留期限（預設 30 天）後，最舊紀錄依保留策略自動清除，資料庫筆數維持在「保留天數 × 每日取樣數」的量級，不再持續成長。
- **SC-006**: 於系統閒置、採預設每 1 秒取樣時，本工具自身平均 CPU 使用率低於 2%、記憶體使用低於 150 MB，使用者於日常操作中無明顯感受。

## Assumptions

- 監控與紀錄範圍限於執行本工具的這台電腦本機，不含遠端或其他主機。
- 沿用本專案既有技術與執行模型（使用者工作階段程序、系統匣、本機加密 SQLite 儲存），本功能為其上新增的資料類別，不另建獨立儲存系統。
- 取樣週期預設為每 1 秒一次，使用者可自訂輸入其他取樣秒數（見 FR-012）。
- 保留策略預設為保留 30 天，使用者可自訂保留天數（見 FR-011）。
- 「網路傳輸與接收速度」逐一網路介面分別紀錄（見 FR-004），整機對外合計流量由各介面加總得出。
- 無獨立 GPU 或僅有內顯的機器，GPU 相關指標以「不適用／無資料」呈現，不視為錯誤。
- 各指標數值以作業系統與裝置驅動所回報者為準，其絕對精度受限於平台可提供的資訊。
