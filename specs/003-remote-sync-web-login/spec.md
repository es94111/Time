## Clarifications

### Session 2026-07-01

- Q：Windows 11 軟體端的登入，其帳號體系與遠端網頁登入帳號體系的關係為何？ → A：同一組帳號——使用者以同一組帳號密碼登入 Windows 軟體與網頁，兩端共用同一遠端帳號系統與工作階段（登出其一不影響另一端既有的本機快取資料，但重新同步需重新登入）。
- Q：多台裝置（多台電腦）資料上傳後，網頁儀表板如何呈現？ → A：以裝置分組——每個使用者帳號可綁定多台裝置，網頁需提供裝置清單與切換檢視，並可查看單一裝置或彙總所有裝置的數據。
- Q：離線或網路不穩時，本機資料與遠端同步如何處理？ → A：離線佇列——本機持續正常記錄與運作，未能上傳的資料先於本機保留並標記「待同步」，恢復連線後自動依時間順序補傳，不遺漏、不重複。
- Q：帳號刪除後，遠端歷史數據的保留與刪除時程為何？ → A：保留 30 天可復原，之後永久刪除。
- Q：連續登入失敗的帳號鎖定門檻與鎖定時間為何？ → A：連續 10 次失敗，鎖定 15 分鐘。
- Q：離線佇列資料量過大時，恢復連線後的補傳策略為何？ → A：固定批次上傳（每批最多 500 筆或 5MB），批次間有節流間隔，直到補傳完成。
- Q：多裝置時鐘誤差導致的時間戳記，遠端保存與網頁時間軸應如何處理？ → A：以遠端伺服器接收資料的時間為準排序與顯示，裝置原始時間僅作輔助參考欄位。
- Q：Windows 軟體與網頁的工作階段（Session）過期時間分別為多久？ → A：軟體端 30 天，網頁端 24 小時。
- Q：一般情況下（使用者未刪除帳號），遠端保存的活動追蹤／系統監控歷史數據要保留多久？ → A：可設定的保留期（使用者自訂天數），逾期後系統自動清除。
- Q：FR-006 提到「僅顯示該帳號本人（或其授權範圍內）的數據」，這裡的「授權範圍」是否代表本功能要支援跨帳號的資料分享／共享？ → A：支援唯讀分享給其他帳號（如家人／團隊檢視）。
- Q：使用者是否可以在網頁上手動解除綁定（移除）某台已同步過的裝置？ → A：可以，使用者可手動移除裝置並停止其未來同步。
- Q：網頁端 24 小時工作階段逾時，是否會因使用者持續操作而自動延展（滑動視窗），還是登入後固定 24 小時到期？ → A：滑動視窗——持續操作可延展至最後操作後 24 小時。
- Q：Windows 軟體與網頁登入時，密碼強度規則應採用哪一種？ → A：僅要求最小長度（如 ≥8 字元），不強制字元種類。
- Q：本機待同步佇列因長時間離線而實際佔滿磁碟空間時（磁碟不足），系統應如何處理？ → A：舊數據優先捨棄——佇列接近磁碟空間上限時，自動捨棄最舊的待同步資料並提示使用者，確保軟體本身不因磁碟滿而發生異常。
- Q：FR-003 提到已登入裝置的資料會「定期且安全地上傳」至遠端，但同步的觸發頻率／機制尚未定義，應採用哪種機制？ → A：固定週期輪詢——背景同步代理每 1 分鐘嘗試上傳一次新累積的待同步資料。
- Q：若使用者在同一台電腦上重新安裝或重置 Windows 軟體後重新登入，系統應如何識別這台裝置？ → A：嘗試沿用原裝置身分——系統偵測到相同硬體特徵時，將新的登入工作階段合併回原裝置紀錄，避免裝置清單重複列出。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建立帳號並登入 Windows 軟體 (Priority: P1)

使用者首次安裝或開啟 Windows 11 軟體時，需要以帳號密碼登入，登入成功後軟體才會開始將本機記錄的活動追蹤與系統監控資料同步至遠端保存。

**Why this priority**: 沒有登入與帳號綁定，資料就無法安全地與特定使用者對應並上傳，這是所有後續遠端功能的前提。

**Independent Test**: 可獨立測試——在全新安裝的軟體上輸入帳號密碼登入，驗證登入成功後本機顯示「已連線」狀態，且工作階段可在重啟軟體後維持（免重複登入，直到工作階段過期或使用者登出）。

**Acceptance Scenarios**:

1. **Given** 使用者尚未登入 Windows 軟體，**When** 輸入正確的帳號與密碼並送出，**Then** 軟體顯示登入成功並開始背景同步資料。
2. **Given** 使用者輸入錯誤的帳號或密碼，**When** 送出登入，**Then** 軟體顯示明確錯誤訊息且不建立工作階段、不進行同步。
3. **Given** 使用者已登入且工作階段有效，**When** 重新啟動軟體，**Then** 軟體自動恢復已登入狀態，不需重新輸入帳密。

---

### User Story 2 - 資料自動上傳並離線補傳 (Priority: P1)

已登入的 Windows 軟體會定期將本機累積的活動追蹤紀錄與系統監控指標，安全地上傳到遠端保存服務；在離線或上傳失敗時，資料先保留在本機待同步佇列，恢復連線後自動補傳。

**Why this priority**: 這是本功能的核心價值——讓資料離開單一裝置、集中保存，並確保網路不穩定時不遺漏資料。

**Independent Test**: 可獨立測試——中斷網路後持續使用電腦一段時間，確認本機仍正常記錄；恢復網路後確認先前累積的資料依時間順序完整出現在遠端／網頁上，沒有遺漏或重複。

**Acceptance Scenarios**:

1. **Given** 軟體已登入且網路正常，**When** 本機產生新的活動或監控資料，**Then** 資料在合理時間內上傳至遠端並可於網頁查詢到。
2. **Given** 網路中斷或遠端服務無法連線，**When** 本機持續產生新資料，**Then** 資料標記為「待同步」並保留在本機，不影響本機既有功能。
3. **Given** 網路恢復連線，**When** 軟體偵測到待同步資料，**Then** 依照原始時間順序自動補傳，且不造成遠端重複資料。

---

### User Story 3 - 透過網頁登入查看個人數據 (Priority: P1)

使用者透過瀏覽器開啟網頁儀表板，以帳號密碼登入後，可以查看自己上傳到遠端的活動追蹤與系統監控歷史數據。

**Why this priority**: 讓使用者能在任何裝置上查看自己的資料，是本功能對使用者最直接可見的價值。

**Independent Test**: 可獨立測試——在瀏覽器中以已註冊帳號登入網頁，驗證登入後可看到先前由 Windows 軟體上傳的資料圖表／清單；以錯誤帳密登入應被拒絕。

**Acceptance Scenarios**:

1. **Given** 使用者尚未登入網頁，**When** 嘗試存取數據頁面，**Then** 系統導向登入頁面，未登入者無法查看任何使用者資料。
2. **Given** 使用者以正確帳密登入網頁，**When** 登入成功，**Then** 可看到自己帳號名下的活動追蹤與系統監控數據。
3. **Given** 使用者登出網頁，**When** 再次嘗試存取數據頁面，**Then** 系統要求重新登入，先前的工作階段不再有效。

---

### User Story 4 - 多裝置檢視與切換 (Priority: P2)

使用者的帳號可能綁定多台電腦（裝置），登入網頁後可以查看裝置清單，選擇檢視單一裝置的數據，或查看所有裝置彙總後的數據；使用者亦可手動移除不再使用的裝置，移除後該裝置需重新登入才能再次同步。

**Why this priority**: 多裝置使用者（如同時使用桌機與筆電）需要能分辨資料來源，屬於重要但非首次可用所必須的加值功能。

**Independent Test**: 可獨立測試——同一帳號在兩台電腦分別安裝並登入軟體後產生資料，於網頁登入後應能看到兩台裝置分別列出，並可切換檢視或查看彙總視圖。

**Acceptance Scenarios**:

1. **Given** 同一帳號已在多台裝置登入並同步過資料，**When** 使用者登入網頁，**Then** 可看到所有已同步過的裝置清單（含裝置名稱與最後同步時間）。
2. **Given** 使用者選擇特定裝置，**When** 切換檢視，**Then** 頁面僅顯示該裝置的數據。
3. **Given** 使用者選擇「彙總所有裝置」，**When** 切換檢視，**Then** 頁面顯示所有裝置數據加總／合併後的結果。
4. **Given** 使用者於裝置清單中選擇移除某台裝置，**When** 確認移除，**Then** 該裝置自網頁裝置清單消失、其既有資料保留於彙總檢視中，且該裝置需重新登入才能再次上傳新資料。

---

### User Story 5 - 帳號與工作階段安全管理 (Priority: P2)

使用者可以在 Windows 軟體與網頁分別登出，變更密碼後所有既有工作階段需要重新驗證，確保遠端保存的個人數據不被未授權存取。

**Why this priority**: 資料一旦上傳到遠端，安全性與存取控制的重要性隨之提高，需要基本的帳號安全管理機制。

**Independent Test**: 可獨立測試——登入後變更密碼，驗證其他裝置或瀏覽器上的既有工作階段被要求重新登入；登出後驗證該工作階段的存取權立即失效。

**Acceptance Scenarios**:

1. **Given** 使用者在 Windows 軟體或網頁登出，**When** 登出動作完成，**Then** 該工作階段立即失效，需重新輸入帳密才能再次存取。
2. **Given** 使用者變更密碼，**When** 變更成功，**Then** 其他既有已登入工作階段（軟體與網頁）在下次操作時被要求重新登入。
3. **Given** 連續多次登入失敗，**When** 失敗次數達 10 次，**Then** 系統暫時鎖定該帳號 15 分鐘並提示使用者。

---

### Edge Cases

- 使用者在 Windows 軟體登入後，若遠端帳號在網頁端被停用或刪除，本機下次同步時應收到明確拒絕並提示使用者重新處理帳號問題，不應無限重試造成資源浪費。
- 本機待同步佇列資料量過大（例如長時間離線）時，恢復連線後以固定批次（每批最多 500 筆或 5MB）搭配批次間節流間隔分批補傳，避免佔用過多頻寬或造成遠端服務過載。
- 本機待同步佇列因長時間離線導致實際佔滿磁碟空間時，系統 MUST 自動捨棄最舊的待同步資料並提示使用者，避免軟體因磁碟空間不足而發生異常或崩潰。
- 同一帳號在多台裝置同時上傳資料時，若裝置時鐘有誤差，遠端保存與網頁時間軸一律以伺服器接收時間為準排序與顯示，裝置本機時間僅作輔助參考欄位，避免顯示上的時序錯亂。
- 使用者刪除帳號時，遠端已保存的歷史數據保留 30 天可復原，30 天後由系統永久刪除（見 FR-012）。
- 一般情況下（帳號未刪除），遠端數據依使用者自訂的保留天數設定自動清除逾期資料；未設定時採系統預設值（見 FR-013）。
- 網頁工作階段採滑動視窗，於使用者最後一次操作起 24 小時無操作後失效；軟體端為固定 30 天，兩者逾時機制不同，使用者體驗上可能出現網頁已登出但軟體仍在同步的情況，屬預期行為並應於介面上明確標示各自的連線／登入狀態。
- 使用者移除某台裝置後，該裝置若仍嘗試上傳資料，遠端 MUST 拒絕並要求該裝置重新登入，不影響其他裝置的正常同步。
- 被分享者僅具唯讀檢視權限，不得修改、匯出授權設定或再轉授權給第三方帳號；授權來源帳號可隨時撤銷分享。
- 使用者於同一台電腦重新安裝或重置 Windows 軟體後重新登入時，系統依硬體特徵偵測為既有裝置並合併回原裝置紀錄；若該裝置先前已被使用者於網頁手動移除，則視為全新裝置重新綁定。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供帳號註冊／登入機制，供使用者於 Windows 11 軟體與網頁共用同一組帳號密碼登入。
- **FR-002**: Windows 11 軟體 MUST 在使用者登入成功前，不將任何本機資料上傳至遠端；本機記錄與監控功能不受登入狀態影響，持續正常運作。
- **FR-003**: 系統 MUST 將已登入使用者本機累積的活動追蹤紀錄與系統監控指標，以固定週期輪詢（背景同步代理每 1 分鐘嘗試上傳一次新累積的待同步資料）安全地上傳至遠端保存服務（如物件儲存或伺服器後端）。
- **FR-004**: 系統 MUST 在網路中斷或上傳失敗時，將待上傳資料保留於本機佇列，並於恢復連線後依原始時間順序、以固定批次（每批最多 500 筆或 5MB）搭配批次間節流間隔自動補傳，不遺漏亦不重複寫入遠端；當本機待同步佇列接近磁碟空間上限時，系統 MUST 優先捨棄最舊的待同步資料並提示使用者，確保軟體本身不因磁碟滿而發生異常。
- **FR-005**: 網頁 MUST 提供登入頁面，未登入使用者無法存取任何屬於特定帳號的資料頁面或 API。
- **FR-006**: 網頁 MUST 在使用者登入後，僅顯示該帳號本人的活動追蹤與系統監控數據，不得存取未經授權的其他帳號資料；系統 MUST 支援使用者將自己的數據以「唯讀」方式分享給其他指定帳號（如家人／團隊檢視），被分享者僅能檢視、不能修改或再分享。
- **FR-007**: 系統 MUST 支援一個帳號綁定多台裝置，並在網頁提供裝置清單（含裝置名稱、最後同步時間）與檢視切換（單一裝置／所有裝置彙總）；使用者 MUST 能於網頁上手動移除（解除綁定）已同步過的裝置，移除後該裝置 MUST 重新登入才能再次同步，其歷史資料則保留於帳號的彙總數據中。系統 MUST 依硬體特徵識別裝置身分——同一台電腦重新安裝或重置軟體後重新登入時，MUST 將新的登入工作階段合併回原有裝置紀錄，不得於裝置清單中重複新增。
- **FR-008**: 系統 MUST 提供登出功能（Windows 軟體與網頁皆須支援），登出後立即使該工作階段失效。
- **FR-009**: 系統 MUST 在使用者變更密碼後，使其他既有工作階段於下次操作時要求重新登入。
- **FR-010**: 系統 MUST 於同一帳號連續 10 次登入失敗後，暫時鎖定該帳號 15 分鐘，以降低密碼猜測攻擊風險。
- **FR-011**: 系統 MUST 對傳輸中與遠端保存的使用者資料進行加密保護（傳輸加密與靜態加密），密碼 MUST NOT 以明文儲存；密碼強度僅要求最小長度（≥8 字元），不強制字元種類混合。
- **FR-012**: 系統 MUST 提供使用者刪除帳號的途徑；帳號刪除後，遠端歷史數據 MUST 保留 30 天以供復原，逾期後 MUST 永久刪除。
- **FR-013**: 系統 MUST 提供使用者可自訂的遠端資料保留天數設定（適用於帳號未刪除的一般情況），逾期資料 MUST 由系統自動清除；未設定時採用系統預設保留天數。
- **FR-014**: 網頁工作階段（Session）逾時 MUST 採滑動視窗機制——工作階段有效期於使用者每次操作後延展，並於最後一次操作起算 24 小時無任何操作後自動失效。

### Key Entities

- **使用者帳號（Account）**：代表一個可登入的使用者身分，包含帳號識別、密碼（加密儲存）、綁定裝置清單、資料保留天數設定、建立時間。
- **裝置（Device）**：代表安裝 Windows 11 軟體的一台電腦，屬於某個使用者帳號，包含裝置識別（依硬體特徵產生，供重新安裝／重置後辨識同一台電腦）、裝置名稱、最後同步時間、同步狀態（含是否已被使用者手動移除）。
- **工作階段（Session）**：代表一次成功登入後的存取憑證，區分軟體端（固定過期時間 30 天）與網頁端（滑動視窗，最後操作後 24 小時無操作即失效），包含建立時間、最後活動時間、過期時間、是否有效。
- **同步紀錄（Sync Record）**：代表一批從本機上傳至遠端的活動追蹤或系統監控資料，包含所屬裝置、資料時間範圍（含裝置本機時間與伺服器接收時間）、上傳狀態（待同步／已完成／失敗）。
- **遠端資料快照（Remote Data Snapshot）**：代表遠端保存的活動追蹤與系統監控資料本體，供網頁查詢與呈現，依帳號與裝置分類保存，依帳號設定的保留天數自動清除逾期資料。
- **分享授權（Share Grant）**：代表一個帳號將自己的數據以唯讀方式授權給另一個指定帳號檢視，包含授權來源帳號、被授權帳號、授權範圍（單一裝置／彙總）、建立時間、是否有效。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者可在 3 分鐘內完成 Windows 軟體登入並看到同步狀態變為「已連線」。
- **SC-002**: 已登入裝置在網路正常情況下，新產生的資料可在 5 分鐘內於網頁查詢到。
- **SC-003**: 模擬 24 小時離線後恢復連線，所有本機累積資料可在合理時間內（依資料量呈線性）完整補傳至遠端，補傳後資料筆數與本機記錄一致（零遺漏、零重複）。
- **SC-004**: 使用者可在 2 分鐘內於網頁完成登入並看到自己至少一台裝置的數據。
- **SC-005**: 90% 的使用者能在不需額外說明的情況下，成功切換單一裝置與彙總檢視。
- **SC-006**: 未登入或以錯誤帳密嘗試存取他人資料的請求，100% 被拒絕，不洩漏任何使用者資料。

## Assumptions

- 使用者已具備基本網路連線能力，且 Windows 11 軟體與網頁儀表板皆透過網際網路存取遠端保存服務。
- 遠端保存服務（S3 相容物件儲存或自建伺服器）由專案團隊自行架設或採購，不在本規格中指定廠商。
- 帳號註冊流程（含忘記密碼、Email 驗證等細節）採業界標準做法，非本規格重點，將於後續設計階段補充。
- 每個帳號綁定的裝置數量沒有嚴格上限，但正常使用情境下預期為個人少量裝置（例如 1～5 台）。
- 待同步佇列與遠端同步機制假設本機磁碟空間足以暫存合理時間內（如數日至數週）累積的資料。
- 遠端資料保留天數的系統預設值、可設定範圍上限，以及唯讀分享功能的邀請／接受流程細節，非本規格重點，將於後續設計階段補充。
